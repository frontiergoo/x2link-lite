# 初期の脅威モデルと検証範囲

対象：管理API/画面、公開転送、RDB、非同期集計、エクスポート・復旧。匿名のリンク作成、任意コード公開、転送先取得、外部通知は実装しない。

|脅威|対策|検証|
|---|---|---|
|管理者の横取り|初期登録はサーバーのCLI、公開登録なし、MFA必須|初回設定・MFA受入、実ブラウザー|
|認証試行・端末紛失|安全なハッシュ、5回失敗で15分制限、OTP側制限、使い捨て回復、再認証、セッション失効|回復コード再使用拒否、試行制限、失効テスト|
|CSRF・セッション漏えい|Django CSRF、管理側same-origin参照方針、Secure/HttpOnly/Strict、ホスト分離|CSRF拒否、ブラウザー送信、公開ホスト管理拒否|
|XSS・任意HTML|自動エスケープ、固定テンプレート、自己ホストCSS/JS、CSP|スクリプト文字列のエスケープ、ページエラー検査|
|他者データの取得・編集|所有範囲をサーバーで検証、フォームのキャンペーン範囲、役割検証|別ワークスペース・閲覧者・エクスポートの受入|
|危険な転送・内部向けURL|HTTP(S)限定、認証情報・制御文字・内部IP・予約ホスト・内部DNSの拒否、自己参照拒否|URLルール・DNS応答テスト|
|登録・更新の競合|一意別名、トランザクション、期待version、公開別名の予約|SQLiteの機能テスト。書き込みワーカーは単一プロセス|
|不正利用と大量登録|100件/時間の共通サービス制限、前段IPレート制限、管理者の緊急停止・個別の不正停止|複製の上限、停止優先、復元で解除されないテスト|
|停止の遅延|302とno-store、DBを毎回参照、障害時503|公開応答・停止・復元の実ブラウザー確認|
|解析障害の巻き込み|転送設定解決と集計の論理分離、計測送信失敗でも転送、欠損ログ|イベント保存失敗を注入して302継続|
|追跡・機密ログ|生IP・完全な参照元・本文を計測に保存しない、本文任意保存、監査は変更項目のみ|エクスポートの認証秘密除外、本文標準非保存|
|バックアップ喪失・削除の巻戻り|SQLiteの整合性バックアップ、別ディスクへ複製、別ファイルへ復元、削除要求の再適用|復旧スクリプトのデータ照合とHTTP転送|

## 未検証と運用上の前提

依存監査・自動テストで全脆弱性を検出できるとは扱わない。外部の独立したセキュリティレビューと実環境の前段設定、TLS、PITR、秘密・ログの保管、運用責任者の確認が必要。転送先は登録時のDNS検査後に変更される可能性がある。P0は転送先をサーバーから取得せず、P1の到達監視はSSRFの追加設計が完了するまで提供しない。公開URLの可用性と解析可用性は、同じDBを使う初期構成では完全な物理分離ではないため、本番の負荷・障害試験と必要な基盤冗長化で評価する。

公開前のcheck --deployではsecurity.W021（HSTSのpreload未設定）が出る。所有ドメインと全関連サブドメインのHTTPS運用・preload登録を確認していないため、自動でpreloadを有効にしない。この警告と判断を運用責任者が確認する。HSTSとSecure Cookieは本番で有効にする。
