# 運用手順（x2link-lite）

## 本番環境

単一Linuxサーバー、SQLite、Gunicorn、HTTPSリバースプロキシの構成を前提とします。PythonはOSのパッケージ管理で導入し、仮想環境は使用しません。SQLiteファイルはローカルの永続ディスクに置き、Webアプリとワーカーの実行ユーザーだけに読み書きを許可します。ネットワークファイルシステム上のSQLite共有や複数サーバー構成は使用しません。

`X2LINK_DEBUG=0`、十分な長さの乱数の `X2LINK_SECRET_KEY`、実ドメインに一致する `X2LINK_ALLOWED_HOSTS`、管理用 `X2LINK_ADMIN_HOST`、HTTPSの `X2LINK_PUBLIC_ORIGIN`、問い合わせ先 `X2LINK_SUPPORT_EMAIL` を設定します。プロキシがTLSを終端する場合は `X2LINK_TRUST_PROXY=1` とし、信頼できるプロキシだけが転送ヘッダーを設定するようにします。秘密情報をGitやシェル履歴へ記録しないでください。

管理画面と公開転送を別ホスト名にし、Nginx等でHTTPS、レート制限、アクセスログ最小化を設定します。`deploy/nginx.conf` は設定例です。証明書パス、ホスト名、静的ファイルの公開パスを実環境に合わせてください。サービス管理下でGunicornを2ワーカー程度、`run_worker`を1プロセス起動します。

Lite版は低〜中程度の書き込み量を想定しています。SQLiteの書き込みロックが増える場合はワーカー数や同時書き込み元を減らし、サーバーを増やさないでください。高い同時書き込み量や複数台構成が必要になった場合は別途データベース構成の見直しが必要です。

## データ保護

毎日バックアップを作成し、別のディスクまたはホストへコピーします。バックアップの暗号化、アクセス制限、保存期限を設定し、定期的に別ファイルへ復元して確認してください。稼働DBを停止せずに整合性のあるコピーを作るには次を使います。

```sh
python3 manage.py backup_database /var/backups/x2link/snapshot.sqlite3
python3 manage.py restore_database /var/backups/x2link/snapshot.sqlite3 --output /var/lib/x2link/restored.sqlite3
```

集計ワーカーは毎分クリックイベントを集計し、日次で期限切れデータとセッションを削除します。詳細イベントは30日、日次集計は397日、監査記録は180日、任意保存した本文結果は7日を保持します。

## 認証回復

管理者パスワードの変更は `python3 manage.py changepassword operator`、ログインセッションの失効は `python3 manage.py revoke_sessions --username operator` で行います。MFAを失った場合はコンソールから `python3 manage.py reset_mfa --username operator` を実行し、次回ログイン時に再登録します。復旧操作は記録し、本人確認と管理者への連絡経路を事前に整備してください。
